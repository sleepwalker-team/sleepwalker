# High-level changes

The recent refactor and documentation merge moved Sleepwalker from a research checkout with implicit imports to an installable framework with explicit data, model, training, deployment, and command-line interfaces. The main branch now contains the merged framework work, documentation branch, and the current HSP masked-autoencoder configuration.

## Packaging and project structure

- Reorganized the Python package under `src/sleepwalker/` and added a `pyproject.toml` build configuration.
- Added the `sleepwalker` console command with a dispatcher for training, evaluation, system evaluation, dataset splitting, EDF mirroring, foundation-model utilities, dry runs, and resume runs.
- Added declared runtime dependencies and optional extras for datasets, foundation models, experiment tracking, documentation, and development.
- Added the MIT license, repository metadata, documentation-site configuration, and a GitHub Actions documentation build.
- Pinned the supported pandas range to `pandas>=2.2,<3` while pandas 3 timestamp behavior is audited.
- Updated ignore rules so model checkpoints, result tables, caches, logs, temporary experiment directories, and generated documentation artifacts are not accidentally committed.
- Removed the old setup entrypoint and obsolete root-level package layout; consumers should install the package or use the configured source checkout.

## Command-line workflows

- Added `python -m sleepwalker.cli.main` and the installed `sleepwalker` entrypoint.
- Added explicit CLI modules for training, dry-run validation, resuming runs, packaged-model evaluation, system evaluation, deterministic EDF split generation, EDF repository mirroring, and foundation-model utilities.
- Kept the lower-level `tools/` scripts as inspectable workflow entrypoints while moving reusable logic into the installed package.
- Training and evaluation now read structured YAML configurations, validate required fields, build callbacks and datasets explicitly, and fail early on incompatible contracts.
- The training CLI exposes a real dry-run path with reduced budgets and temporary logging, making configuration checks possible before a full run.
- Evaluation validates package contracts, dataset geometry, class mappings, output paths, folds, patient filters, and prediction-table schemas before processing recordings.
- System evaluation writes structured JSONL records and optional Feather prediction tables, supports overwrite checks, and preserves metadata for later aggregation.

## Dataset and signal handling

- Added a process-shared `EDFCache` backed by memory-mapped NumPy arrays. Workers coordinate cache misses and reuse complete recordings without sending signal arrays through the manager process.
- Added `PairedDataset` for composing multiple native expert datasets at common target anchors. It plans input envelopes, reuses compatible metadata and sample calls, and delegates signal loading and preprocessing to each component dataset.
- Added explicit dataset input specifications and stronger validation for channel groups, units, sampling frequency, temporal geometry, labels, and preprocessing.
- Improved EDF signal conversion, grouped channel handling, resampling, filtering, normalization, and missing-channel diagnostics.
- Added or completed normalizers for EEG, respiration, saturation, pulse, and generic signals, with optional normalization where a foundation model requires it.
- Improved dataset initialization and patient filtering, including strict and non-strict modes, deterministic split handling, and explicit rejection strategies.
- Preserved multiple disjoint valid regions after patient or event filtering instead of collapsing them into one continuous interval. Sampling now respects retained `start_offsets`.
- Added support for dataset cloning, labelled/unlabelled conversion, repeated views, channel aliases, assumed units, and shared cache injection.
- Added clearer target construction for single-task and multitask data, including target resolution, target offset, soft boundaries, partial labels, and event mappings.
- Added and refreshed configurations for HSP, Ruhrland, SHHS, SleepEDFx, and foundation-model examples, including external evaluation definitions for Ruhrland 2024 and pre-2024 cohorts.

## Model and deployment interfaces

- `BaseModel` now requires `input_spec() -> (shape, meta)`. Concrete models declare input geometry and layout instead of relying on implicit dataset inference.
- `Run` and packaged-model validation now use `model.input_spec()` and check it against dataset channels, sampling frequency, sequence length, and layout.
- Added explicit package manifests and classification contracts for task names, class order, sequence length, target resolution, target offset, and multitask output definitions.
- Strengthened packaged-model save/load and compatibility checks, including mapping inputs for composed models and regular `BTC` inputs for single-stream models.
- Added timestamp-aware prediction utilities, Feather read/write helpers, task and patient metrics, confusion-matrix aggregation, and dependency-aware evaluation helpers.
- Added `StackedClassifierModel` for synchronous probability composition of heterogeneous classifier packages.
- Added temporal interval utilities for native prediction grids, overlap slicing, upsampling, downsampling, and contract-aware alignment.
- Added frozen, task-local, joint, rate-only, and naive composition regimes, with correction heads and explicit expert execution envelopes.
- Added `PairedDataset` integration to stacked models so each expert retains its native input contract while sharing the requested prediction window.
- Removed the older `ModelGraphClassifier` path and associated generic graph tests in favor of packaged and stacked-model interfaces.
- Updated model families and packaged classifiers to the explicit input-spec and classification-contract APIs.

## Training and trainer changes

- Consolidated training lifecycle code around `BaseTrainer`, `RunCfg`, explicit loaders, samplers, callbacks, checkpointing, and target preparation.
- Added or refreshed training utilities for patient-balanced sampling, multitask loading, masked embedding training, multilabel training, and sequence classification.
- Fixed masked-autoencoder checkpoint handling so intermediate and best checkpoints write model, optimizer, and scheduler state, and trainer state is initialized consistently before training.
- Added scheduler and checkpoint tests covering training steps, validation, best-model selection, and resume behavior.
- Added explicit centered target offsets to active train configurations, matching the temporal center used by each model and target resolution.
- Preserved the current HSP masked-autoencoder experiment's six channel groups: EEG, EOG, RIP, SPO2, LEG-EMG, and ECG.
- Retained the required MAE dependencies and tracker integration for the HSP experiment while reconciling them with the current trainer and configuration APIs.

## Documentation

- Added a complete documentation site with getting-started material, how-to guides, API references, dataset and model references, troubleshooting, performance notes, packaging instructions, and a roadmap.
- Added documentation for data loading, channel definitions, annotations, target coverage, windowing, patient sampling, trainer lifecycle, prediction packages, model inspection, and foundation-model heads.
- Added diagrams and figures for dataset preparation, channel grids, target coverage, windowing, cache and sampling performance, and trainer execution.
- Added contributor, citation, people, and project-overview pages.
- Migrated legacy design notes into `maintenance/legacy-docs/` and added maintenance reports describing repository inventory, extraction, integration, and validation checkpoints.
- The documentation build runs in strict mode in CI and is generated with Zensical and Mkdocstrings.

## Tests and validation

- Added focused tests for EDF caching, grouped signal conversion, dataset initialization, patient sampling, split generation, packaged models, stacked models, system evaluation, CLI tools, schedulers, sequence models, multitask classifiers, and masked-autoencoder training.
- Separated paper-specific tests from framework tests while retaining generic evaluation, packaging, and composition coverage in this repository.
- The integrated framework test suite passed with **619 tests passed and 16 skipped** on the supported pandas version.
- A focused trainer/configuration run passed **22 tests**, including masked-autoencoder checkpoint paths.
- The strict documentation build passed.
- A built wheel was imported in an isolated environment, and the installed `sleepwalker --help` command completed successfully.

## API changes to check when updating downstream code

- Install Sleepwalker and import from `sleepwalker` under `src/`; do not rely on removed checkout-relative package paths.
- Implement `input_spec()` on every custom model and return both input shape and metadata such as layout, channels, sampling frequency, and sequence length.
- Put dataset-combination code under `sleepwalker.datasets.MultiDataset` and use the current dataset APIs for initialization and filtering.
- Use `trim_event(...)` for event-based trimming; the older wake-specific `trim_wake(...)` helper is gone.
- Add target resolution and target offset to training and package contracts where predictions represent intervals rather than individual samples.
- Use `PackagedModel` classification contracts and the installed CLI for evaluation instead of calling removed legacy tools directly.
- Expect stricter validation of channel groups, class mappings, package geometry, prediction schemas, and output files.
