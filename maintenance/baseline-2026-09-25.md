- Configs assume `iclr2026/configs`, `iclr2026/models`, and `results/iclr2026` relative to the Sleepwalker checkout. Shell scripts also assume a local venv and tmux/GPU execution.
- HSP manifests contain absolute `/raid/...` paths with participant identifiers. Keep dataset access manifests deliberate when publishing; do not treat these as portable examples.
- Archived configs reference removed `iclr2026.replacement` and older model APIs. An old replacement implementation exists under ignored `old/iclr2026`; archive reproduction is distinct from the active workflow.
- Saved model/checkpoint loading relies on Python class/module paths. Removing `ModelGraphClassifier` and its compatibility code can affect older payloads. The synthetic current-format smoke does not validate all existing checkpoints.

**Dependency recommendation:** use an installed Sleepwalker dependency pinned to a reviewed commit, with editable installs for local development. Integrate the docs branch's packaging before validating that boundary. A submodule alone would not resolve imports, paths or missing packaged modules.

The main baseline selected `test_edf_cache`, `test_edf_to_df_grouped`, `test_stacked_classifier_model`, `test_multitask_classifier_model`, `test_multilabel_trainer`, `test_deployment`, `test_base_trainer`, `test_train_tool`, and all five `test_iclr_*` modules. Logs and JUnit XML contain exact test IDs and failures.

Existing failures:

1. **Timestamp unit assumptions with pandas 3:** 110 resampling tests fail with nanosecond frequencies incompatible with microsecond-resolution dates. Two evaluation tests produce incorrect dependency conditioning; code converts timestamps to integers and mixes them with nanosecond durations. Outside the sandbox, two EDF cache tests and three prediction tests also expose incorrect window selection/empty reads. All 117 of these affected checks pass with pandas 2.3.3. This is evidence for a dependency/API compatibility issue; fixing code or constraining supported pandas versions remains future work.
2. **Stale dataset arguments:** three training-tool tests fail because `BaseDataset.__init__` no longer accepts `target_resolution`. Active `configs/train` examples still supply it. The same failures remain with pandas 2.3.3: `test_active_training_component_graphs_construct`, `test_dry_run_changes_training_not_just_validation`, and `test_runcfg_from_checkpoint_reuses_serialized_trainer_and_model`.
3. **Packaging:** `setup.py` uses `find_packages`, omitting directories without package initializers, including `trainer` and `datasets/augmentation`. Editable/source-checkout imports mask this failure. Python metadata still says `>=3.7` despite newer syntax. The docs branch adds the missing initializers, `src` packaging, runtime dependencies, and a `>=3.10` requirement; this needs a post-merge wheel test.

The pandas 2 comparison used a separate `/tmp/sleepwalker-baseline-20260925/pandas2` directory, with `pytz` and `tzdata`, exposed only through `PYTHONPATH`; the baseline venv was not downgraded. Five initial EOF errors were caused by sandbox-blocked multiprocessing sockets, so the pandas comparison also ran outside the sandbox. Deprecation warnings remain in that comparison and are retained in its log.

The synthetic smoke uses existing test fixture models via an explicit checkout `PYTHONPATH`. Its subprocesses run from the temporary output directory. It validates the current paper packaging workflow, not successful extraction or independence from the checkout.
